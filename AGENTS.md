# Wiki.js - Agent Guide

This document provides essential information for AI coding agents working on the Wiki.js project.

## Project Overview

Wiki.js is a modern, lightweight, and powerful wiki application built on Node.js. It is designed as an open-source, self-hosted wiki platform supporting multiple content formats (Markdown, HTML, AsciiDoc) with a rich feature set including authentication, search, storage, and analytics modules.

- **Version**: 2.x
- **License**: AGPL-3.0
- **Repository**: https://github.com/Requarks/wiki
- **Documentation**: https://docs.requarks.io/

## Technology Stack

### Backend
- **Runtime**: Node.js (>= 10.12, recommended 20.x)
- **Framework**: Express.js
- **API**: GraphQL (Apollo Server)
- **Database ORM**: Knex.js + Objection.js
- **Authentication**: Passport.js with multiple strategies
- **Template Engine**: Pug

### Frontend
- **Framework**: Vue.js 2.6.x with Vue Router and Vuex
- **UI Library**: Vuetify 2.3.x
- **Build Tool**: Webpack 4.x
- **Transpiler**: Babel
- **Styling**: SCSS/Sass
- **Icons**: Material Design Icons

### Supported Databases
- PostgreSQL 9.5+ (recommended, required for HA mode)
- MySQL 8.0+ (5.7.8 partially supported)
- MariaDB 10.2.7+
- MS SQL Server 2012+
- SQLite 3.9+ (development/testing only)

## Build and Development Commands

### Prerequisites
- Node.js >= 10.12 (20.x recommended)
- Yarn package manager
- One of the supported databases

### Installation
```bash
yarn install
```

### Development Mode
```bash
yarn dev
```
Starts the development server with:
- Hot Module Replacement (HMR)
- Auto-restart on server file changes
- Type `rs` + Enter in terminal for manual restart

### Production Build
```bash
yarn build
```
Compiles frontend assets to `assets/` directory.

### Production Start
```bash
yarn start
```

### Testing
```bash
# Run all tests (ESLint + Pug lint + Jest)
yarn test

# Run only unit tests
jest

# Run E2E tests with Cypress
yarn cypress:open
```

## Code Style Guidelines

### JavaScript/Vue.js
- **Standard**: JavaScript Standard Style (configured via `eslint-config-requarks`)
- **Vue.js**: Strongly recommended rules (`plugin:vue/strongly-recommended`)
- **Parser**: babel-eslint
- **ECMAScript**: ES2017

Key rules:
- No semicolons
- 2-space indentation
- Single quotes for strings
- No trailing spaces
- Space after keywords (if, for, etc.)

Run linting:
```bash
eslint --format codeframe --ext .js,.vue .
```

### Pug Templates
Configuration in `package.json` under `pugLintConfig`:
- 2-space indentation
- Single quotes for attributes
- Lowercase tags and attributes
- No duplicate attributes
- Require strict equality operators

Run linting:
```bash
pug-lint server/views
```

### SCSS/CSS
- Use SCSS syntax
- Global variables in `client/scss/global.scss`
- Component-scoped styles in Vue files

## Database Migrations

Migrations are located in:
- `server/db/migrations/` - Production migrations
- `server/db/migrations-sqlite/` - SQLite-specific migrations
- `server/db/beta/` - Beta-to-stable migration helpers

Migration files follow naming convention: `version.js` (e.g., `2.5.137.js`)

To create a new migration, add files to appropriate directories for each database type.

## Module System

Wiki.js uses a modular architecture for extensibility:

### Authentication Modules
Location: `server/modules/authentication/`
Each module is a directory containing `authentication.js` implementing a Passport.js strategy.

### Storage Modules
Location: `server/modules/storage/`
Handles content syncing to external storage (Git, S3, etc.)

### Search Modules
Location: `server/modules/search/`
Search engine implementations (Elasticsearch, PostgreSQL full-text, etc.)

### Rendering Modules
Location: `server/modules/rendering/`
Content processing pipeline (Markdown, HTML sanitization, diagrams, etc.)

### Creating New Modules
1. Create directory under appropriate category
2. Implement required interface (check existing modules for examples)
3. Module is auto-loaded on server start

## GraphQL API

- **Schema**: Defined in `server/graph/schemas/` (`.graphql` files)
- **Resolvers**: `server/graph/resolvers/` (auto-loaded)
- **Directives**: `server/graph/directives/`
- **Subscriptions**: Implemented via `graphql-subscriptions` PubSub

## Testing Strategy

### Unit Tests (Jest)
- Location: `server/test/`
- Run: `jest`
- Helpers have corresponding `.test.js` files

### E2E Tests (Cypress)
- Location: `dev/cypress/`
- Configuration: `cypress.json`
- Run: `yarn cypress:open`
- CI runs against: PostgreSQL, MySQL, MariaDB, SQLite

### Writing Tests
- Unit tests for helpers and utilities
- E2E tests for critical user flows
- All tests must pass before merging

## Configuration

Main configuration file: `config.yml` (copy from `config.sample.yml`)

Key sections:
- `db`: Database connection
- `ssl`: SSL/TLS settings (including Let's Encrypt)
- `pool`: Database pool options
- `logLevel`: Logging verbosity
- `ha`: High-availability mode (PostgreSQL only)

## Deployment

### Docker
Multi-stage Dockerfile at `dev/build/Dockerfile`:
- Stage 1: Build assets (node:20-alpine)
- Stage 2: Production image (node:20-alpine)

Published images:
- Docker Hub: `requarks/wiki`
- GitHub Container Registry: `ghcr.io/requarks/wiki`

### CI/CD Pipeline (GitHub Actions)
1. **Build**: Compile assets, create Docker images
2. **Cypress**: Run E2E tests against multiple databases
3. **ARM Build**: Build ARM64 images
4. **Windows Build**: Create Windows bundle
5. **Release**: Publish multi-arch manifests, GitHub release

### Manual Deployment
1. Build assets: `yarn build`
2. Install production deps: `yarn --production`
3. Configure `config.yml`
4. Start: `yarn start` or `node server`

## Security Considerations

### Authentication
- Supports 20+ authentication strategies via Passport.js
- 2FA support via `node-2fa`
- JWT tokens for API access
- Session management with `express-session`

### Content Security
- DOMPurify for HTML sanitization
- XSS prevention via `xss` module
- Content Security Policy headers
- File upload restrictions via mime-type validation

### Database Security
- Parameterized queries via Knex.js
- SQL injection prevention through Objection.js ORM
- SSL/TLS support for database connections

### Dependencies
- `patch-package` applies security patches
- Regular dependency updates via PRs
- Lock file (`yarn.lock`) ensures reproducible builds

### Secrets Management
- Never commit `config.yml` with real credentials
- Use environment variables for sensitive data (e.g., `DATABASE_URL`)
- SSL certificates can be loaded from files

## Development Tips

### Global WIKI Object
The global `WIKI` object is available throughout the server code:
- `WIKI.config` - Configuration values
- `WIKI.models` - Database models
- `WIKI.logger` - Winston logger instance
- `WIKI.servers` - HTTP server instances
- `WIKI.IS_DEBUG` - Development mode flag

### Adding New Dependencies
```bash
yarn add <package>
# For dev dependencies:
yarn add -D <package>
```

### Patching Dependencies
```bash
# Make changes to node_modules/<package>
yarn patch-package <package>
# Patches are applied automatically on install via postinstall hook
```

### Debugging
- Set `logLevel: debug` or `logLevel: silly` in config.yml
- Use `WIKI.logger.debug()` for debug output
- Node.js inspector: `node --inspect server`

### Hot Reload Limitations
Server files are watched and auto-restart on changes, but:
- Webpack-compiled assets require a rebuild
- Database migrations require manual restart
- Configuration changes require restart

## Common Tasks

### Add a new GraphQL query
1. Add type definition in `server/graph/schemas/`
2. Add resolver in `server/graph/resolvers/`
3. Restart server

### Add a new database model
1. Create file in `server/models/`
2. Extend `Model` from Objection.js
3. Define `tableName`, `jsonSchema`, `relationMappings`
4. Export and it will be auto-loaded

### Add a new authentication strategy
1. Create directory in `server/modules/authentication/`
2. Implement `authentication.js` following existing patterns
3. Restart server

### Add a new content renderer
1. Create directory in `server/modules/rendering/`
2. Implement `renderer.js` with `render()` method
3. Add to rendering pipeline in admin UI
